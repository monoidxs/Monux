Кратко: `mono help <команда>`. Подробно: `mono manual <команда>`.
Технический режим: `mono manual backend <команда>`.

## `delete`

```text
DELETE

Удаляет файлы, каталоги и учётные записи пользователей.

По умолчанию файлы и каталоги отправляются в корзину, если окружение её поддерживает.
Если корзина недоступна, Mono сообщает об ошибке и не удаляет объект окончательно.

--permanent
    Удаляет объект без помещения в корзину. Восстановление через корзину невозможно.

--force
    Разрешает удаление непустого каталога. Не отменяет подтверждение,
    права доступа и защиту критических путей.

--dry-run
    Ничего не изменяет. Показывает объект, способ удаления и уровень риска.

Уровни риска:
    🟢 обычный пользовательский файл или каталог
    🟡 системный путь: требуется особая осторожность
    🔴 критические каталоги системы: удаление запрещено

Mono запрашивает подтверждение yes перед удалением. Символическая ссылка удаляется
как ссылка, её целевой объект сохраняется. Каталог с данными требует --force.
--permanent и --force можно сочетать. Неизвестные параметры вызывают ошибку.

Учётная запись: mono delete user alex. Домашний каталог сохраняется.
Системные пользователи защищены; --force и --permanent для учётных записей не применяются.
Для имени, начинающегося с --, используйте mono delete -- <имя> или путь ./<имя>.

Примеры:
    mono delete test.txt
    mono delete ./build --force
    mono delete test.txt --permanent
    mono delete ./build --force --permanent --dry-run
```

## `diagnose`

```text
DIAGNOSE

Без аргумента или с system проверяет 12 разделов системы. Сводка показывает OK, WARNING, ERROR, UNKNOWN (не удалось проверить) или SKIPPED (нет данных/поддержки). Подробности в общей сводке выводятся для проблем и недоступных проверок. Имя раздела запускает только его проверку.

Problems found — число разделов с WARNING или ERROR, а не число независимых причин. UNKNOWN/SKIPPED считаются отдельно. OK относится только к описанной проверке, а не гарантирует исправность оборудования.

Проверки ничего не исправляют и не меняют настройки. Только network/system выполняют внешние пробы: имя archlinux.org и TCP-порт 443 адресов 1.1.1.1 или 9.9.9.9. Это не тест всего интернета, TLS или HTTP. Ошибки DNS и TCP различаются.

Память: использовано 100% минус доступная память; предупреждение от 85%, ошибка от 95%. Показывается крупнейший видимый процесс по RSS, а не сумма процессов приложения. Диск: те же пороги для заполнения файловых систем. CPU: предупреждение при минутной нагрузке от 1.5 на логический процессор; это включает ожидание ввода-вывода.

Температура: общий ориентир 85/95 °C, реальные пределы зависят от устройства. Батарея: при разрядке предупреждение от 20% вниз, ошибка от 10% вниз. Отсутствие датчиков в WSL не выдаётся за OK.

Файловые системы: только режим корневой файловой системы, без проверки целостности и ремонта. Службы: список отказавших. Boot: состояние текущей загрузки. Hardware: ошибки ядра текущей загрузки; в WSL физическое оборудование не проверяется. Logs: количество видимых ошибок за последние 15 минут, без простыни журнала.

Внешние системные проверки ограничены двумя секундами каждая; сетевые подключения — по 700 мс. Общий запуск обычно занимает несколько секунд, при таймаутах дольше. Код 0 означает, что отчёт построен; найденные проблемы отражаются в нём. Неверные аргументы дают код 1.

Примеры:
    mono diagnose
    mono diagnose system
    mono diagnose memory
    mono diagnose network
    mono diagnose services

--dry-run
    Ничего не изменяет. Показывает будущие действия.
```
